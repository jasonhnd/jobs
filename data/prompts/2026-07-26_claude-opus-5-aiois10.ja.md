## タスク

あなたは日本の労働市場アナリスト。与えられた職業 extract を **AIOIS-10 v1.0** の 10 次元で採点し、2 つの指数を計算して strict JSONL で出力する。

- 各次元は **0.0〜10.0、小数第 1 位まで**。
- **現行生成 AI（2026 年時点）の実力**を基準に判定する。「5 年後にできそう」ではなく「今できるか」。
- **高得点 ≠ 仕事が消える。** Transformation（変化の大きさ）と Displacement（仕事が減るリスク）は別物であり、多くの高 Transformation 職は「置換」ではなく「再構成」される。

## 10 次元の定義

向き: ▲ = AI が届く部分（高いほど影響が進む）／ ■ = 人間の強み（高いほど守られる）／ ◐ = その他の調整。

| 次元 | 名称 | 向き | 定義 |
|------|------|------|------|
| D1 | 認知・生成暴露 | ▲ | 文章・情報・分析・プログラムなど、現在の生成 AI が単独でほぼ完結できる仕事の割合。データ入力・機械翻訳・定型的な文章作成ほど高い。 |
| D2 | 定型反復 | ▲ | ルールが定まり、繰り返しが多く、結果が予測できる度合い。従来型の自動化やソフトウェアでも置きかえやすい。 |
| D3 | 身体・現場性 | ■ | 身体動作・手先の器用さ・移動・現場での目視や手作業がどれだけ要るか。ロボットでしか置きかえられず、ソフトウェアより遅く高コスト。 |
| D4 | 判断と責任 | ■ | 正解のない局面での重い判断と、特定の人間が負うべき法的・倫理的な責任。 |
| D5 | 対人・情動 | ■ | 対面のやりとり・共感・信頼構築・ケア・説得・交渉。人と人の関係そのものが価値になる度合い。 |
| D6 | 創造性 | ■ | 既存の組み合わせ（生成 AI が得意）ではなく、真に新しいアイデア・作品・解を生み出す度合い。 |
| D7 | 資格・安全の壁 | ■ | 免許・専門職規制が人間を要求する、あるいは失敗が人命に関わるため人間の立ち会いが要る度合い（◐ 調整と ■ 強みの両面）。 |
| D8 | 自動化の費用対効果 | ◐ | 自動化コスト（設備・導入）が、置きかえる人件費より安いか。安いほど置きかえが進む（▲ 影響と ◐ 調整の両面）。 |
| D9 | 需給・制度（日本版） | ◐ | 技術的に置きかえ可能でも、実際に置きかわるかを左右する地域要因。導入力・雇用慣行・人手の過不足。**深刻な人手不足では AI は脅威ではなく助けになる（D9 は低くなる）**。本標準で唯一、国・地域ごとに採点する次元。 |
| D10 | 雇用の将来性 | ▲ | 今後 5〜10 年でその仕事の人数・価値がどれだけ増減するか。AI による減少圧力と、新たに生まれる仕事の力を合わせて見る（高い = 減少方向）。 |

各次元は 0.0 =「その性質がほぼ無い」〜 10.0 =「その性質が極めて強い」の連続値として、extract の職務内容に即して**直接付与**する。帯に丸めない（3.9 は 3.9 のまま、正直に）。

## 指数の計算（モデル自身が計算して出力する）

1. `E = (D1 + D2) / 2`
2. `transformation` = E を小数第 1 位に丸める（ちょうど .X5 のときは切り上げ。例 4.65 → 4.7）
3. `M = (D3 + D4 + D5 + D6 + D7) / 5`
4. `P = (D8 + D9) / 2`
5. `displacement_raw = E × (1 − M/10) × (0.6 + 0.4 × (P + D10) / 20)`
6. `displacement` = displacement_raw を 0〜10 に clamp し、小数第 1 位に丸める（.X5 切り上げ）
7. `ai_risk = transformation`（**完全一致**）

計算例: D1=4.8, D2=4.4, D3=5.0, D4=6.5, D5=5.8, D6=3.0, D7=4.2, D8=3.6, D9=2.8, D10=3.5 のとき
E=4.6 → transformation=4.6=ai_risk; M=(5.0+6.5+5.8+3.0+4.2)/5=4.9; P=(3.6+2.8)/2=3.2;
displacement_raw=4.6×(1−0.49)×(0.6+0.4×(3.2+3.5)/20)=4.6×0.51×0.734=1.722 → displacement=1.7。

公式・重みを変更したり、displacement を公式によらず感覚で付けたりすることを禁止する。

## 出力契約（strict JSONL）

職業ごとに **1 行、以下の JSON object のみ**。コードフェンス・前置き/後置きの説明文・配列 wrapper・複数行整形 JSON・コメントは**すべて禁止**。

```
{"id": <int>, "ai_risk": <num>, "rationale_ja": "<日本語1文>", "confidence": <0〜1>, "aiois": {"d1": <num>, "d2": <num>, "d3": <num>, "d4": <num>, "d5": <num>, "d6": <num>, "d7": <num>, "d8": <num>, "d9": <num>, "d10": <num>, "transformation": <num>, "displacement": <num>}}
```

- `id` は extract に記載された整数 ID をそのまま使う。
- すべての score は**数値型**（数値文字列は禁止）、0〜10、**小数第 1 位まで**（6.95 のような 2 桁小数は invalid）。
- `confidence` は 0〜1（採点への自信度）。
- `rationale_ja` は**空でない日本語 1 文**。付けたスコアと矛盾しないこと（例: moat を高く付けたのに「守られない」と書かない）。
- `aiois` の 12 field（d1〜d10, transformation, displacement）は**すべて必須**。null・省略は invalid。
- 上記以外の追加 field は**禁止**。
- 採点できない職業があれば、その ID の JSON 行を出力せず、**明示的にエラーとして報告**する。推測での補完・他モデルへの fallback は禁止。
